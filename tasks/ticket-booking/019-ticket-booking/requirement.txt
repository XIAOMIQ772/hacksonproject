火车票预订演示系统\n\n一个小型火车票预订网站，访客可以注册账号、登录系统、搜索已发布的车次，并在登录后提交乘客信息完成订票。\n账号、登录会话和已确认订单需要持久化，页面刷新或服务重启后仍可恢复。\n系统只实现教学演示所需的完整主流程，不包含在线支付、退票、改签、取消订单、座位库存扣减、历史订单列表和时刻表管理。\n首页视觉参考：![首页](./reference/homepage.png)\n\n## REQ-1 注册旅客账号\n\nValidation 契约：应用必须支持直接访问 `/register`，首页必须提供可点击的 `Register` 链接进入该页面。注册页必须提供以下稳定且唯一的中文可访问名称，供 Playwright 使用 `getByLabel` 或 `getByRole` 定位，控件必须与对应 label 原生关联，不得依赖 CSS class、DOM 顺序或 placeholder：`用户名` 为必填文本输入框；`登录密码` 为必填密码输入框，并显示随输入动态变化的三段密码强度指示器；`确认密码` 为必填密码输入框；`证件类型` 为必填原生下拉选择框，选项包括“请选择证件类型”（初始值）、“居民身份证”、“护照”、“港澳居民来往内地通行证”、“台湾居民来往大陆通行证”和“外国人永久居留身份证”；`姓名` 为必填文本输入框；`证件号码` 为必填文本输入框；`优惠（待）类型` 为必填原生下拉选择框，初始提示为“请选择乘客类型”，选项包括“成人”、“儿童”、“学生”、“残疾军人”和“其他优惠类型”；`邮箱` 为可选 email 输入框；`国家/地区代码` 为手机号组合控件中的必填下拉选择框，默认值为 `+86`，并至少提供 `+84` 等国际区号；`手机号` 为必填文本输入框；必须有 accessible name 包含 `服务条款` 或 `隐私政策` 的必选复选框；必须有 accessible name 为 `下一步` 的提交按钮。有效数据提交后必须调用注册接口、创建登录会话并导航回 `/`，首页显示提交的用户名和 accessible name 为 `Sign out` 的退出链接，刷新后仍保持登录；缺失、格式错误、密码不一致、重复用户名或重复邮箱、未同意协议时，必须显示可见的中文错误消息，且不得创建账号或登录会话。\n实现旅客注册页面和注册接口，从首页点击 `Register` 进入。\n页面提供用户名、登录密码、确认密码、证件类型、姓名、证件号码、优惠（待）类型、邮箱、国家/地区代码、手机号、服务条款和隐私政策复选框以及“下一步”按钮。\n前端负责必填提示和基础交互，后端必须再次完成全部校验，不能依赖前端结果。\n用户名、登录密码、确认密码、证件类型、姓名、证件号码、优惠（待）类型、国家/地区代码和手机号均为必填，邮箱为可选，服务条款和隐私政策必须同意。\n姓名去除首尾空格后应包含 2–100 个非空白字符；\n证件号码只能包含 6–30 个 ASCII 字母、数字或连字符；\n证件类型必须从页面提供的有效选项中选择，优惠（待）类型必须从页面提供的有效选项中选择，手机号必须与国家/地区代码组合通过校验。\n用户名只能包含 3–32 个 ASCII 字母、数字、连字符或下划线。\n邮箱填写时必须是完整有效的地址且不超过 254 个字符。\n登录密码长度为 12–128 个字符，并至少包含大写字母、小写字母、数字和特殊字符；\n确认密码必须一致；\n用户必须接受服务条款和隐私政策。\n用户名和邮箱都必须唯一，邮箱重复判断忽略大小写。\n注册接口使用服务端生成的账号标识和会话令牌，禁止返回密码或密码摘要。\n有效提交将账号安全写入持久化文件、创建登录会话并返回首页；\n页面显示当前用户名和“退出登录”。\n任何缺失、格式错误或重复数据都显示明确错误，不得创建账号或会话。\n账号写入应采用安全的读改写流程，避免文件损坏和只写入一半的数据。\n演示数据使用唯一用户名 `tb-user-<时间戳>-<随机值>`、由该用户名生成的有效邮箱、密码 `Valid-password-123!`、姓名 `Ticket User <时间戳>-<随机值>`、证件类型 `护照`、证件号码 `P<时间戳数字>`、优惠（待）类型 `成人`、国家/地区代码 `+84` 和有效手机号 `912345678`。\n重复场景复用相同用户名或邮箱；\n无效示例包括用户名 `bad username!`、邮箱 `not-an-email`、密码 `short`、两次密码不一致、缺少证件号码或未勾选协议。\n可选视觉参考：![注册页面](./reference/register.png)\n\n**Type:** ATOMIC\n**Dependencies:** None\n\n**Scenarios:**\n\n- 使用有效资料注册并保持登录\n  - **GIVEN:** 一名未登录访客准备了唯一且符合规则的账号和旅客资料。\n  - **WHEN:** 访客填写注册表单、接受服务条款并点击“下一步”。\n  - **THEN:** 系统保存账号并创建会话，首页显示用户名和“退出登录”，刷新页面后仍保持登录。\n- 拒绝缺失或格式错误的资料\n  - **GIVEN:** 注册资料存在必填项缺失、格式错误、日期无效、弱密码、确认密码不一致或未接受协议。\n  - **WHEN:** 访客提交注册表单。\n  - **THEN:** 页面显示对应错误，系统不创建账号，也不创建登录会话。\n- 拒绝重复用户名或邮箱\n  - **GIVEN:** 系统中已经存在相同用户名或大小写不同但内容相同的邮箱。\n  - **WHEN:** 访客再次提交注册。\n  - **THEN:** 系统返回重复账号错误，原账号保持不变且不产生新的账号或会话。\n\n## REQ-2 登录和退出账号\n\nValidation 契约：应用必须支持直接访问 `/login`，首页必须提供可通过 Playwright `getByRole('link')` 定位的 `登录` 或 `Login` 入口。登录页只需实现账号密码登录核心功能，不需要实现二维码、扫码登录、宣传内容、忘记密码或其他扩展功能；必须提供与 label 原生关联且可通过 Playwright `getByLabel` 或 `getByRole` 定位的控件：中文可访问名称 `用户名或邮箱`（同时兼容 `Username or email`）的文本输入框，中文可访问名称 `密码`（同时兼容 `Password`）的密码输入框，以及中文可访问名称 `立即登录` 或 `登录`（同时兼容 `Login` 或 `Sign in`）的提交按钮。登录输入框必须支持用户名或邮箱，服务端应去除账号标识首尾空格，用户名按保存值匹配，邮箱匹配忽略大小写，密码必须完全匹配且区分大小写。有效用户名和密码登录、使用大小写不同的邮箱登录、错误密码或不完整凭据登录、未知账号登录是必须通过的四个核心场景；错误密码、不完整凭据和未知账号必须显示完全相同的通用错误消息，错误语义可使用中文“无效凭据”“登录失败”“账号或密码错误”或兼容英文 `invalid credentials`、`login failed`、`sign-in failed`、`incorrect credentials`、`incorrect password`、`wrong credentials`、`wrong password`，且不得泄露账号是否存在。成功登录后必须导航到 `/`，首页显示当前用户名和可访问名称为 `退出登录` 或 `Sign out` 的退出链接，刷新后仍保持登录；失败登录不得显示退出链接，也不得创建或改变登录会话。\n实现登录页面、登录接口、会话恢复和退出登录。\n从首页点击“登录”进入登录页面。\n登录页面提供“用户名或邮箱”“密码”和“登录”控件。\n提交时去除账号标识首尾空格；\n用户名按保存值匹配，邮箱匹配忽略大小写，密码必须完全一致。\n后端从持久化账号文件读取用户，验证成功后生成不可预测的会话令牌并保存会话，随后返回首页。\n首页在未登录状态显示“注册”和“登录”，登录后显示当前用户名和“退出登录”。\n浏览器通过安全的会话凭据恢复身份，刷新页面后仍应保持登录。\n点击“退出登录”后，服务端删除或失效当前会话，浏览器清除会话凭据并恢复未登录导航状态；\n再次刷新不能恢复已经退出的会话。\n用户名、邮箱或密码为空，账号不存在，或者密码错误时，统一显示不泄露账号是否存在的登录失败提示，并保持未登录状态。\n接口响应不能返回密码、密码摘要或其他用户的资料。\n演示时使用通过 REQ-1 创建的唯一账号，正确密码为 `Valid-password-123!`；\n有效示例可使用用户名或邮箱并允许首尾空格，无效示例使用 `incorrect-password` 或不存在的邮箱。\n可选视觉参考：![登录页面](./reference/login.png)\n\n**Type:** ATOMIC\n**Dependencies:** REQ-1\n\n**Scenarios:**\n\n- 使用用户名登录并恢复会话\n  - **GIVEN:** 系统中存在一个已注册账号，访客当前未登录。\n  - **WHEN:** 访客使用带有可选首尾空格的用户名和正确密码登录。\n  - **THEN:** 首页显示保存的用户名和“退出登录”，刷新页面后会话仍然有效。\n- 使用邮箱登录\n  - **GIVEN:** 系统中存在一个带有有效邮箱的已注册账号。\n  - **WHEN:** 访客使用大小写不同的邮箱和正确密码登录。\n  - **THEN:** 系统识别同一账号并建立登录会话。\n- 拒绝无效凭据\n  - **GIVEN:** 登录标识或密码为空、不存在或不正确。\n  - **WHEN:** 访客点击“登录”。\n  - **THEN:** 页面显示统一的登录失败提示，不透露账号是否存在，也不创建会话。\n- 退出当前会话\n  - **GIVEN:** 用户已经登录并位于任意公开页面。\n  - **WHEN:** 用户点击“退出登录”。\n  - **THEN:** 当前会话失效，页面恢复“注册”和“登录”入口，刷新后仍保持退出状态。\n",
